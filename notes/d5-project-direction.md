# 项目方向卡｜MIA_Ether · Wallet Transfer Watch

## 1. 一句话

监听 **Ethereum Sepolia** 上测试 ERC-20 合约的 `Transfer` 事件；当我的测试钱包单笔转出达到自设阈值时，由 **Lasna** 的 Reactive 合约判断，并在 **Ethereum Sepolia** 的 `AlertRecorder` 合约写入一条可核验的告警。正式项目可在测试完成后考虑支持其他网络；本阶段只使用测试网和测试代币。

## 2. 赛道

**赛道 2：Set It and Forget It（个人自动化）**。这是一个我会给自己的测试钱包持续开启的转出监控工具。它按链上事件自动运行，不需要我一直盯区块浏览器；没有承诺 1 秒内阻止转账，也没有把 AI 当成运行时组件。

## 3. 目标用户与真实场景

目标用户是管理多个钱包、想及时发现大额代币转出的个人开发者或小团队。现在通常靠人工查看区块浏览器、钱包通知，或者自建 7×24 小时的 RPC 监听机器人；人工检查可能漏掉事件，自建机器人要维护服务器、重连、去重和签名密钥。这个项目把事件订阅、阈值判断和回调交给 Reactive，告警以链上事件留下证据。若要推送 Telegram / 微信通知，仍需额外的通知服务；链上告警本身不等于即时消息，也不能撤销已发生的转账。

## 4. 第 2 周最小 Demo

1. 在 Sepolia 部署测试 ERC-20，向测试钱包发放测试代币。
2. 在 Lasna 部署 Reactive 合约，只订阅该代币的 `Transfer`，并把 `from` 过滤为我的测试钱包；判断单笔金额是否达到阈值，并按源链交易哈希与日志序号去重。
3. 在 Sepolia 部署 `AlertRecorder`，通过官方 Callback Proxy 接收回调；验证服务提供者和 Reactive 合约地址，记录转出地址、接收地址、金额和源链交易标识。
4. 实际发送一笔低于阈值和一笔达到阈值的测试转账，证明前者不产生告警、后者产生 `Transfer → react() → callback` 三笔可查交易；同时测试未授权调用被拒绝、处理上限和资金不足时的行为。

D4 已用模板 `Ping` 事件[跑通相同的三段链路](d4-cross-chain-callback.md)。第 2 周要把源事件和回调内容换成上面的钱包监控用例。
